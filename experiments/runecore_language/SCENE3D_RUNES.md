# RuneCore 3D v0.13 — Rune/Shaep scene bridge

**Status:** deterministic experimental 3D scene and element encoding, not a trained LLM, chemical bonding model, or live shared-world server.

This release connects the original fixed-position Rion/Ring/Rune/Glyph/Shaep structural language with the previously tested three-coordinate scene. The lake/shore/building example is the same 3,604-cell world and its 248 compact storage spans as v0.12. The added layer shares eight scene-group descriptors in SQLite instead of copying full ring encodings into every cell.

## What is stored

- `scene3d_runes.sqlite3`: durable SQLite scene with `(x,y,z)` voxels, scene-group references, source hashes, and eight shared descriptors. The viewer never advances its clock or rewrites the scene when a camera moves.
- `scene3d_runes.json`: deterministic compact export, schema `RuneCore.Scene3D/2`, with 248 cell spans and the shared Rune descriptors. Can be regenerated byte-for-byte.
- `viewer3d_runes.html`: offline HTML with embedded scene export, visual-only canvas, first-person camera, mobile movement control, and Rion detail as the viewer approaches lake cells.
- `scene3d.py`: preserved v0.12 coil, storage, scene creation, projection and tests.
- `runecore_language.py` and `ring_contacts.py`: preserved experimental RuneCore language, periodic Glyph catalog and generic ring matcher.
- `scene3d_runes.py`: new scene bindings, spatial query, spherical display coils, ring phasing, and scene integrity checks.

## Confirmed model inputs

The H–H–O example uses **three Runes** (two H Glyphs, one O Glyph), with only the owner's supplied four- and eight-bit ring structures. Its outer oxygen ring alternates raw exposure and computed contacts:

```
11111111
11101110
11111111
11011101
11111111
10111011
11111111
01110111
```

The contact result is derived from the selected model's mirrored sector assignments; the selection rule and alternating substeps remain **hypotheses** and do not establish chemistry. Other scene materials (wood, stone, glass, shore, grass, roof) retain `UNKNOWN_NOT_INFERRED` atomic composition. They are never assigned invented atomic ring encodings. The apparent lake blue, roof red and so forth are **artist-authored appearance metadata stored in Shaep bindings**, not spectral colors derived from real atomic physics.

## Two different coils

1. `scene3d.coil_xyz`: exact owner's integer `(x,y,z)` ordering, with first ten coordinates preserved and optional spherical distance mask for sparse 3D storage.
2. `scene3d_runes.spherical_coil_sites`: fixed sites on a Fibonacci-sphere angular coil for depicting a Rune's individual Rion `0/1` positions in three dimensions. Bits change sites as each ring rotates, but site locations remain fixed. This is illustrative mathematics, not a quantum orbital.

## Running it

From this folder:

```
python -m unittest discover -p 'test_*.py' -v
python scene3d_runes.py --database my_scene.sqlite3 --export my_scene.json
python build_viewer.py
```

`scene3d_runes.py` deliberately refuses to overwrite a previously generated database. For regenerating examples, use a new database name. To view, open `viewer3d_runes.html` in a browser. The HTML needs no server and no external JavaScript libraries.

Desktop: WASD to move; mouse drag to rotate; Q/E or Shift/Space to move vertically; R resets camera. On mobile, use the lower-left touch joystick and drag the 3D scene to rotate view. As you approach the lake, occupied Rion sites appear as filled dots and connectable 0 positions as hollow circles. Visuals only; no debug overlay is drawn in the scene.

## Scientific and operational boundaries

This is a procedural scene assembler and deterministic symbolic simulator, not a trained RuneCore LLM. The rendered 3D spheres are visualization of binary patterns, not observed electron positions. No actual material palette, density, force, energy, optics, H–O molecular bonding or biological behavior is derived from atomic simulation here. A static browser file does not perform unattended computation once it is closed. Source/code existence is not proof of deployed runtime reachability. The project database remains authoritative; Old ReLiC provenance records are not silently rewritten.

**Next falsifiable milestone:** derive a new, unseen assembly from a generic mechanism, predict its 3D behavior independent of its label, and compare against a baseline and known physical reference data. Do not claim an LLM until a documented trained model, weights, held-out tests and evidence exist.
