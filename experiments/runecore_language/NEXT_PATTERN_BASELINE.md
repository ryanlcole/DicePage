# RuneCore — first trained next-Rion baseline

Status: EXPERIMENTAL SYNTHETIC LEARNING, not a language model large enough
to be called an LLM, not established physics, not live Shaelvien authority.

## Corrected owner terminology
Rion = binary position; Ring = rotating Rion positions; Rune = encoded element
consisting of rings; Glyph = periodic-table identity and atomic number;
Shaep = candidate assembly of interacting Runes; Repeat = recurrence.
The generic trained predictor learns only rotating Ring positions. It does not
learn chemistry, discover an element, or create a Shaep.

## Reproducible training

From the existing experiments/runecore_language directory:

    python -m unittest -v test_next_pattern_model
    python next_pattern_model.py --out /tmp/runecore-next-rion-weights.json

No paid model API, external training corpus or GPUs are needed. This is a
small, count-based conditional next-bit predictor. Weights are dictionaries
of observed next Rion counts, conditional on CW/CCW direction and adjacent
bit positions. It is trained on Ring.at() transitions generated by the
existing bounded interpreter, rather than real physical measurements.

Train dataset: 16 distinct rotation classes per width over widths 7 through
12, with both directions and multiple phases, deterministic seed 17.
Held-out dataset: 20 distinct classes per width over widths 13 through 18,
with both directions and multiple phases, deterministic seed 29.
Entire ring STRUCTURES and WIDTHS are disjoint between training and test.
A leak check explicitly rejects overlapping structures or widths.

Tests require:
- exact reproducibility of trained count dictionaries and evaluation
- learned 100 percent bit accuracy on the generated held-out rules
- better accuracy than the no-learning "copy input" baseline
- exact transitions for owner-supplied H/O test patterns
- generated test samples never enter training data
- corrupted model/unknown conditional context reports UNKNOWN, not invented
  agreement or a forced factual claim
- labels/provenance cannot claim private canonical project records
- slot identity and underlying Ring/rune source remain untouched.

This 100 percent refers ONLY to the synthetic deterministic Ring.at rule
and is mathematically uninteresting as evidence of real-world intelligence:
the oracle already knows the rotation rule. It is a deliberately small
baseline for future sequence-model comparisons and protocol hardening.

## Model artifact and scope
GitHub Actions workflow test-runecore-learned.yml executes unit tests,
trains the reproducible count model and uploads a short-lived
runecore-next-rion-synthetic-weights artifact. The artifact is explicitly
not a production-language-model checkpoint. It is separate from any
private Shaelvien or ReLiC project database.

Next falsifiable milestone: sequence modeling on held-out, *nonperiodic*
ring contacts, noisy input, multi-Rune interactions, and independent
transition sources, with a registered null baseline. If a model is called
a RuneCore LLM, require architecture, weights, training provenance,
data rights, adequate held-out evaluation and documented limitations.

No canon promotion, production deployment, private record ingestion,
MCP write or owner-identity representation is authorized by this research.
