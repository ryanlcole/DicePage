ReLiC Projects is the bounded project-memory layer of ReLiC. It keeps different projects from collapsing into one AI memory and preserves the evidence needed to reconstruct what exists, what changed, what failed, what replaced it, and what remains unknown.

Definition

ReLiC is the project mind, not the project database.

GitHub, AWS, source documents, tests, runtime telemetry, and other systems remain evidence and implementation. ReLiC preserves continuity between those states. Canon remains explicitly governed truth. An AI may query and reason over ReLiC, but connecting an AI does not make that AI ReLiC's persistence or canon authority.

Continuity chain

A useful project memory must survive time, not just summarize today.

1 · ObserveRecord a bounded event with source and status.
2 · PreserveKeep prior state and failures instead of silently overwriting them.
3 · RelateAssociate evidence with the correct project partition.
4 · VerifySeparate claims from inspected code, tests, deployment, and runtime evidence.
5 · ExplainReconstruct why the current state exists and what preceded it.
6 · RetrieveExpose bounded read-only context to ChatGPT and other clients.

Current implementation

Bounded project targets

project_memory_targets.json defines project targets and preservation rules. The drift guard maps changed paths to those targets and warns when a change deserves review.

WARN_ONLY matters: ReLiC may warn about drift; it does not veto an authorized human decision.

Local project mind

The PC work was a real predecessor.

Historical evidence includes a local ReLiC interface with named mind nodes such as Frontal, Temporal, Parietal, Limbic, Occipital, World, and WaveCore, plus a localhost launcher. That is preserved as historical project evidence, not presented here as the current ReLiC architecture.

What judges should test

Ask for reconstruction, not recall.

A strong test is to start with a fresh AI context and ask for a project report: what exists, what is current, what failed, what became obsolete, why changes occurred, and what remains unknown. The answer should be reconstructable from durable evidence rather than depending on conversational memory.

Known gap

Historical migration is still part of the work.

The continuity audit found important historical project material that was not present in the recovered bounded ReLiC event snapshot. Migration candidates are designed to remain append-only, private, human-approved, and non-canon by default.

A missing event is evidence of a continuity gap, not evidence that the historical event never existed.
