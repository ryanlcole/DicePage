## Live discovery

The deployed application publishes an intentionally unlisted reference at:

`/Game/_shaelvien-language.html`

and a machine-readable discovery manifest at:

`/Game/.well-known/shaelvien-language.json`

The hidden/unlisted page is for discovery, not access control. No credential, secret, private permission table, hidden world fact, or private semantic payload belongs there.

## Assistant bootstrap rule

Before creating or changing Rune, Glyph, SHAEP, CHID, CCTV, semantic-stream, permission-resolution, perception, or compact instruction code:

- read the canonical contract, architecture reference, and current registry;
- do not invent meanings for unknown semantic IDs/opcodes;
- preserve `Identity != representation` and `server truth -> authorized perception`;
- preserve provenance and truth-domain metadata;
- keep authentication secrets and unrevealed world state on the trusted/server side;
- version semantic changes instead of silently changing an existing ID's meaning.

A fresh ChatGPT conversation does not automatically inherit this language merely because these files exist. A repo-aware, connected, or explicitly directed session can use these discovery surfaces to reload the same rules rather than reconstructing them from conversational memory.

If the contract, architecture reference, and implementation disagree, report the disagreement instead of silently reconciling it.
