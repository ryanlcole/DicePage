# Shaelvien Creative Workplace Contract

Status: owner-directed active product doctrine  
Date: 2026-09-26

## Core principle

Difficulty in one task is information about fit, support, or training. It is not evidence that a creator has no value.

Shaelvien must help GameMasters discover where they create well, keep weak areas from blocking production, and let strong disciplines become bridges into disciplines they want to learn.

## Three independent dimensions

Shaelvien must not collapse these into one hierarchy:

1. **Recursion — where the work exists.** World → Region → Local → Instance → deeper authored identity.
2. **Creative state — how mature the work is.** Capture → Shape → Compare → Refine → Combine → Produce → Play.
3. **Medium — how the idea is expressed.** Narrative, Scripted, Visual, Audio, Responsive/System, Performance, Production.

One scene may contain several media at different maturity states while retaining one recursive identity.

## Audience versus creator presentation

Players experience scenes, places, encounters, performances, and consequences.

GameMasters may see the creative anatomy behind those scenes: drafts, alternates, notes, visuals, audio, scripts, triggers, placeholders, pros/cons, production readiness, and discarded/table ideas.

Separate creator tools must not force the audience to understand creator departments.

## Private Workbench

Every creator needs a private place where unfinished work is legitimate.

A Workbench item may be:

- Active
- Tabled
- Discarded but recoverable
- Placeholder
- Promoted toward production

Table and Discard are different. Table means "not now." Discard means "not pursuing this version." Neither silently destroys history.

Permanent deletion is a separate explicit action.

Creative drafts are private working material. Moving something into canonical world/campaign truth requires a separate explicit production action and the normal authority checks.

## Universal creative pipeline

All media share one recognizable production grammar:

**CAPTURE → SHAPE → COMPARE → REFINE → COMBINE / IRON IN → PRODUCE → PLAY**

The specialized tool may change. The workflow grammar should not.

"IRON IN" means the creator has chosen to make the draft part of the working composition. It does not mean public release.

## Start where the creator already thinks

The ordinary Create entry asks, in effect, **What do you have?**

Valid starting points include:

- an idea
- words
- a picture
- a sound
- a map
- a mechanic
- something already playable

No starting medium outranks another.

## Creative-fit model

Do not assign one global skill grade to a person.

Track or let the creator declare independent dimensions by discipline:

- current strength/capability
- enjoyment/preference
- growth interest

These may disagree. Strong but disliked work must not automatically become the person's assigned role. Weak but desired skills must not be hidden from them.

Initial disciplines include Story, Visual, Audio, Systems, Performance, and Production.

The user owns these declarations. Observed behavior may justify a suggestion, not a forced reclassification.

## Workplace model

For a task, the creator may eventually choose among:

- do it personally
- ask for teaching/help
- use assistance
- assign a collaborator with authority
- use a legitimate placeholder
- table the task

A solo GameMaster must be able to keep production moving through placeholders instead of being blocked by a weak discipline.

Collaborative projects should route work by consent, authority, interest, and demonstrated fit rather than a simplistic pass/fail model.

## Assistance Gradient

Assistance is selected per discipline/task, not imposed globally.

### Teach

Use when the creator asks to learn.

Explain concepts, why they matter, and the smallest useful practice. Whenever possible, let the creator perform the meaningful action.

### Help

Use when the creator asks to accomplish something or overcome a blocker.

Reduce theory. Solve the immediate obstacle, preserve authored work, and surface only the information needed to continue.

### Suggest

Use when the creator is exploring.

Offer alternatives, missing pieces, comparisons, and optional next steps. Suggestions do not alter authored state.

### Predict

Use when the creator is familiar, trained, or explicitly enables predictive assistance.

Prepare likely next tools/actions, preselect non-destructive context, and surface likely production needs. Prediction prepares; it does not presume.

### Quiet

Use when the creator wants an instrument rather than a teacher.

Do not add commentary unless required for safety, authority, failure recovery, or an explicit request.

## Familiarity and expertise

Declared expertise and observed familiarity are not the same.

Declared professional/domain familiarity may justify a denser interface immediately.

Observed repeated successful use may justify a gentle offer such as "Keep Layers open by default?" It must not silently graduate the user into a more complicated interface.

Professionals may deliberately return to simple tools for rough work.

## Strengths as teaching bridges

When teaching a weaker or developing discipline, translate through a stronger discipline when useful.

Examples:

- visual → narrative: panels become beats
- narrative → visual: focus/conflict/consequence become composition
- audio → narrative: tension/release becomes pacing
- systems → narrative: state/choice/consequence becomes story structure
- performance → writing: spoken delivery becomes editable dialogue

The goal is transfer of understanding, not forcing every creator into the same learning path.

## Assistance agency rule

The greater the consequence, the earlier prediction must stop before commitment.

Prediction may preview or prepare framing, layers, suggested transitions, draft alternatives, or likely next tools.

Prediction must not silently:

- delete authored work
- publish/release
- overwrite production assets
- spend currency/tokens
- change permissions
- assign collaborators
- move private drafts into canonical world truth

Those require explicit creator action and existing authority.

## Creator-shell information architecture

The long-term creator-facing product has three major faces:

- **CREATE** — private Workbench, alternatives, learning, production preparation
- **WORLD** — recursively place and relate authored content
- **PLAY / RUN** — exercise the resulting experience

Specialized studios remain available as instruments rather than becoming the primary landing-page taxonomy.

## Stable spatial grammar for creative instruments

Where a canvas/editor is appropriate:

- left = tool/instrument
- center = current work
- right = material/asset/draft selection
- bottom = contextual actions / the creator's hands
- top = persistent modifiers and assistance state

The user should learn this spatial grammar once even as the available instrument grows from foundation-level tools to professional controls.

## Progressive depth

Foundation tools must produce legitimate playable content.

Additional depth is offered, not imposed:

- Foundation
- Craft
- Studio
- Production
- Mastery

These describe tool depth, not human worth or a permanent user rank.

No interface may automatically become substantially more complicated merely because the software believes the user improved. Offer deeper tools and let the creator accept them.

## Multiple input paths, one action graph

Touch, mouse, keyboard, controller, speech, switch input, accessibility shell, and future agent interfaces should call the same canonical actions.

Different transports must not implement different world truth.

Keyboard and professional users may use dense shortcuts. Touch should remain recognizable. Speech should favor discrete commands. Drag and gestures are convenience paths, never the only essential path.

## AI / EI role

Assistance behaves more like faculty and production staff than autonomous creative authority.

Useful roles include instructor, assistant, critic, editor, translator between media, producer, and playtester.

AI/EI may help fill a temporary skill gap or create a placeholder. It must preserve provenance and must not silently redefine the creator's intent or promote its own output to production truth.

## Preservation rule

Existing specialized tools remain available while Create becomes the simpler front door.

Migration to this model must preserve current working WorldBuilder, Region, Local, Campaign, Asset, card, accessibility, and advanced tool behavior unless a deliberate replacement has passed regression testing.
